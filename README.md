# 单核 SRTF 抢占调度与完成时刻核验后端

离线单核 CPU 作业调度服务：输入作业 ID、到达时刻与总 CPU 需求，按**最短剩余处理时间优先（SRTF）**生成执行片段、完成时刻、周转时间与等待时间。仅做逻辑时间计算：不启动真实线程、不改变 Windows 调度优先级、不模拟锁 / I/O / 多处理器 / 随机到达，也不真实等待。

技术栈：TypeScript + Node.js（内置 `node:http` 与 `node:sqlite`，零运行时第三方依赖），Windows 本地运行，不需要 Docker / WSL / 外部服务。要求 Node.js ≥ 22（`node:sqlite` 目前会打印 ExperimentalWarning，属正常提示）。

## 快速开始

```powershell
npm install        # 仅安装开发依赖 typescript / @types/node
npm run build      # 编译到 dist/
npm test           # 构建并运行全部测试（含随机交叉核验）
npm run demo       # 运行内置样例 A(0,8) B(1,4) C(2,2) 并逐单位核验
npm start          # 启动 HTTP API（默认端口 0 = 自动选择空闲端口）
```

数据库默认保存在项目内 `data/srtf.db`，可用环境变量 `SRTF_DB` 覆盖；服务端口用 `--port N` 或环境变量 `PORT` 指定。

## 调度规则（rules version: `srtf/1.0`）

- **事件驱动抢占**：就绪集合中选择剩余需求最少者。新作业到达时，先结算当前作业从上一事件到本时刻的执行，再加入本时刻全部到达作业，最后重新选择。
- **完成优先**：当前作业恰好在某时刻完成时，先记录完成再选择下一项；绝不会在剩余量耗尽后继续执行。
- **空闲**：无可运行作业时直接跳到下一到达时刻，并记录空闲区间（甘特表中 `jobId = null`）。
- **平局规则（固定，与输入顺序无关）**：
  1. 剩余需求相同时，**已在运行的作业继续**（相等不抢占）；
  2. 没有可保留的当前作业时，按**到达时刻**升序；
  3. 再按 **ID 的 ASCII 字典序**（ID 限定为 `[A-Za-z0-9_]`，避免区域排序差异）。
- 每次真正换作业才形成 `preempt` 事件；同秒到达但不构成抢占时记录 `arrival` 事件并说明未抢占原因；不产生零长度片段；相邻同作业片段在最终甘特表中合并。
- 无上下文切换开销。

## 统计口径（三者不可混算）

- **周转时间** = 完成时刻 − 到达时刻
- **等待时间** = 周转时间 − 总需求
- **首次响应时间** = 首次开始时刻 − 到达时刻

时刻区间归属为**左闭右开** `[start, end)`：完成时刻不再属于该作业；最后完成之后查询运行者返回 `null`。

## 已知样例

输入 `A(0,8) B(1,4) C(2,2)`，输出片段 `A:[0,1) B:[1,2) C:[2,4) B:[4,7) A:[7,14)`，完成时刻 14 / 7 / 4，等待时间 6 / 2 / 0。`npm run demo` 可直接复现并打印事件解释。

## CLI

```
node dist/cli.js <命令>
  serve [--port N]          启动 HTTP API（默认自动选择空闲端口）
  import <file> [--name X]  导入作业集（JSON 数组 / {"jobs":[...]} / CSV: id,arrival,burst）
  list                      列出作业集与运行
  preview <jobsetId>        预览输入（保留原始输入顺序）
  run <jobsetId>            执行完整调度（重复请求返回同一冻结结果）
  report <runId>            查看汇总报告（片段表 + 统计表）
  events <runId>            导出全部调度事件（含前后就绪剩余量与选择理由）
  at <runId> <time>         查询指定时刻运行者（左闭右开）
  job <runId> <jobId>       查看单作业经历
  verify <runId>            逐时间单位独立模拟核验
  demo                      内置样例演示
```

## HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 健康检查与规则版本 |
| POST | `/api/jobsets` | 导入作业集 `{name?, jobs:[{id,arrival,burst}]}` |
| GET | `/api/jobsets` / `/api/jobsets/:id` | 列表 / 预览输入 |
| POST | `/api/jobsets/:id/schedule` | 执行完整调度；重复请求返回冻结结果（`frozen: true`） |
| GET | `/api/runs` / `/api/runs/:id` | 运行列表 / 汇总报告（含片段与统计） |
| GET | `/api/runs/:id/events` | 导出调度事件 |
| GET | `/api/runs/:id/at/:t` | 指定时刻运行者 |
| GET | `/api/runs/:id/jobs/:jobId` | 单作业经历 |

错误响应统一为 `{"error": {"code": "...", "message": "..."}}`，校验失败 400，不存在 404。

## 错误码

| 代码 | 含义 |
| --- | --- |
| `E_BAD_JSON` | 请求体 / 文件不是合法 JSON |
| `E_NO_JOBS` | 作业集为空或不是数组 |
| `E_INVALID_ID` | ID 非 `[A-Za-z0-9_]` 或超长 |
| `E_DUP_ID` | 作业 ID 重复 |
| `E_NEGATIVE_TIME` | 时刻 / 需求为负 |
| `E_NON_INTEGER` | 非整数或非数值 |
| `E_NON_POSITIVE_BURST` | 需求为零 |
| `E_TOO_MANY_JOBS` | 作业数超过上限（10000） |
| `E_OVERFLOW` | 加法越过安全整数上限 |
| `E_JOBSET_NOT_FOUND` / `E_RUN_NOT_FOUND` / `E_JOB_NOT_FOUND` | 对象不存在 |
| `E_BAD_REQUEST` | 其他参数 / 路由错误 |

## 持久化与一致性

- SQLite 保存作业集、规则版本、事件、片段与汇总报告；指纹（规则版本 + 规范化作业内容的 SHA-256，与输入顺序无关）用于去重。
- 修改任一作业需求会产生新的作业集与新的运行，**不覆盖旧时间线**；重复分析请求返回同一冻结结果；重启后读取报告无需重新调度。
- 批次校验失败时不写入任何数据（事务保证，不写半份报告）；不同作业集互不影响。
- 上限：作业数 ≤ 10000；所有时间为非负安全整数，运行前检查求和不越过 `Number.MAX_SAFE_INTEGER`。

## 测试与核验

`npm test` 运行 16 个测试：已知样例、相等不抢占、同秒多到达、完成与到达重合、开头 / 中间空闲、乱序一致性、字典序平局、左闭右开边界、全部错误码、200 组随机小规模输入的**事件驱动 vs 独立逐时间单位模拟**交叉核验（并检查每作业执行总长恰等于需求、片段不重叠、等待非负），以及冻结复用、重启读取、版本隔离、失败不落库等持久化行为。

## 适用范围与限制

- 仅离线逻辑时间计算，一次性完成中等规模调度；不实现实时暂停、定时器或复杂增量数据结构。
- 逐单位核验命令 `verify` 仅支持总时刻数 ≤ 1,000,000 的小规模输入。
- 单核、无上下文切换开销、无 I/O 与锁建模；`node:sqlite` 为实验性 API（Node 25 下稳定可用，会有警告提示）。
